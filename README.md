# チケット管理（個人用）

自分の担当タスクをチケット単位で管理する Web アプリです。
作業状況・優先度・期限・作業メモをまとめて管理できます。
インストールしたあとは自分の PC の中だけで動き、データもブラウザの中に保存されます。外部のサーバーにデータを送ることはありません。

---

## 1. 実装済みの機能

| 分類 | 機能 |
| --- | --- |
| チケット管理 | 新規登録 / 詳細表示 / 編集 / ゴミ箱へ移動 / IDの自動採番（T-0001 形式。削除したIDは再利用しない） |
| ゴミ箱 | 削除したチケットはゴミ箱へ移り、一覧・ボード・ダッシュボードには表示されない。削除直後の通知の「元に戻す」、またはゴミ箱画面から元に戻せる。ゴミ箱画面で「完全に削除」「ゴミ箱を空にする」を行うと、確認ダイアログのあとで完全に削除される（元に戻せない） |
| 詳細画面 | タイトル直下に「ステータス・優先度・期限」の概要を表示。「基本情報」「対応状況」「更新情報」のカードに分けて表示。ステータスはボタン1回で変更でき、現在のステータスは色と✓で示す。期限日の近くに「期限を2日過ぎています」などの説明を表示。「戻る」リンクは開く前の画面（一覧の検索条件・ボード・ダッシュボード）に戻る |
| 編集画面 | 「編集中」の表示と青枠で閲覧中と区別。保存・キャンセルは画面下部に固定。変更がないうちは保存できない。保存していない変更がある状態で画面を移動しようとすると確認ダイアログ、タブを閉じる・再読み込みの前にはブラウザの確認を表示。保存の成功・失敗を通知（失敗時は入力内容を残す）。作業メモの編集にも同じ確認がある |
| 案件 | 「案件マスター」画面で案件名と色（パステルカラー12色）を登録・編集・削除できる。チケットに案件を1つ設定すると、ボードのカードと一覧の行の背景が案件の色になり、案件名のラベルが表示される。一覧・ボードで案件による絞り込みができる。使用中の案件を削除すると、確認のうえ該当チケットは「案件なし」になる（チケット自体は残る） |
| 登録項目 | タイトル（必須）、詳細説明、案件、ステータス、優先度、カテゴリ、担当者（初期値「自分」）、開始予定日、期限日、作業メモ、作成日時・更新日時・完了日時（自動） |
| ステータス | 未着手 / 進行中 / 保留 / 完了。一覧・ボード（セレクトボックス・ドラッグ＆ドロップ）・詳細画面（ボタン）からその場で変更できる |
| 一覧 | テーブル表示。期限超過は赤、本日期限はオレンジ、7日以内は黄色の印で表示し、期限なしは「未設定」と表示。行またはタイトルをクリックすると詳細画面、「編集」で編集画面を開く。スマートフォンではカード状の縦並びで表示 |
| ボード | ステータスごとの4列（未着手・進行中・保留・完了）にカードを表示。カードを別の列へ**ドラッグ＆ドロップするとステータスが変わる**。画面上部のゴミ箱へドロップするとゴミ箱に移動する。列の中は、未完了の列が期限日の近い順、完了列が完了日時の新しい順（完了列は最新30件まで表示）。ドラッグできない環境向けに、カードにもステータスの切り替え欄がある |
| 検索・絞り込み | キーワード（タイトル・詳細説明・ID。スペースで区切るとAND検索）、ステータス（「未完了」も選べる）、優先度、カテゴリ、期限（超過・本日・7日以内・期限なし）、期限日の範囲。「未完了」「優先度「高」」「期限超過」「本日期限」はクイック絞り込みのボタン1回で切り替えられる。複数の条件を組み合わせられる。適用中の条件は件数の横にチップで表示され、個別に解除（×）またはまとめてリセットできる（並び替えはリセット後も維持） |
| 並び替え | 期限日（近い順・遠い順）/ 優先度（高い順・低い順）/ 作成日時（新しい順・古い順）/ 更新日時 |
| ダッシュボード | 「要対応」（期限超過・本日期限・7日以内・優先度「高」の未完了・未完了）と「ステータス別」（全件・未着手・進行中・保留・完了）の件数。件数をクリックすると、同じ条件で絞り込んだ一覧へ移動する（集計と一覧の条件は同じ定義を使用）。期限超過・本日期限・7日以内・未完了で優先度「高」のチケットの一覧 |
| 作業メモ | 詳細画面で直接編集できる。「日時を挿入」ボタンで作業ログを残しやすい |
| データ | ブラウザ（localStorage）に自動保存。JSON ファイルへのバックアップ（エクスポート）と復元（インポート）。最終バックアップ日時の表示と、7日以上空いたときの注意表示。復元前に、ファイルの内容（作成日時・件数）の確認と、現在のデータの自動退避（「復元前の状態に戻す」で取り消せる） |
| 操作性 | Ctrl + Enter で保存、入力エラーは項目ごとに表示、保存結果は画面右下に通知、スマートフォンでも操作できるレイアウト |

### 期限・優先度の表示ルール（全画面共通）

| 状態 | 表示 |
| --- | --- |
| 期限超過 | 赤：「期限超過 ○日」 |
| 本日期限 | オレンジ：「本日期限」 |
| 7日以内（明日〜7日後） | 黄色：「あと○日」 |
| 8日以上先 | 通常の表示（日付のみ） |
| 期限未設定 | 「未設定」 |
| 完了済み | 期限の警告を出さず、日付を控えめに表示 |

- 判定は日付単位（`YYYY-MM-DD`）で、今日の日付は実行時点のPCの日付を使います。判定処理は [src/lib/deadline.ts](src/lib/deadline.ts) の1か所にまとめ、一覧・ボード・詳細・ダッシュボードで共通に使います。
- 優先度は「▲高（赤）」「■中（オレンジ）」「▼低（グレー）」のように、色に加えて記号と文字で表示します。

### 完了チケットの扱い（共通ルール）

- ステータスを「完了」にすると、**完了日時**が自動で記録されます。
- 「完了」から別のステータスに戻すと、完了日時は消えます。
- 完了済みのチケットは、期限を過ぎていても「期限超過」「本日期限」「7日以内」には含めません。

| 項目 | 内容 |

## 3. セットアップ手順（初回のみ）

### 3-1. Node.js をインストールする

1. https://nodejs.org/ja を開き、**LTS（推奨版）** をダウンロードしてインストールします。
   - Windows では、PowerShell で次のコマンドを実行してもインストールできます。
     ```powershell
     winget install --id OpenJS.NodeJS.LTS -e
     ```
2. インストール後、**VS Code やターミナルをいったんすべて閉じてから開き直し**、次のコマンドでバージョンが表示されることを確認します。
   ```powershell
   node -v
   npm -v
   ```

### 3-2. 必要なパッケージをインストールする

ターミナル（PowerShell）でこのフォルダ（`ticket-app`）に移動して、次のコマンドを実行します。

```powershell
cd ticket-app
npm install
```

`node_modules` フォルダが作成されれば完了です。

## 4. 起動方法

```powershell
cd ticket-app
npm run dev
```

ブラウザが自動で開きます。開かない場合は、ブラウザで **http://localhost:5173/** を開いてください。
終了するときは、ターミナルで `Ctrl + C` を押します。

> **注意**：データは「ブラウザ」と「URL（ポート番号を含む）」ごとに保存されます。
> 毎回同じブラウザで同じ URL（http://localhost:5173/）を開いてください。
> データが見えなくならないよう、ポートは 5173 番に固定しています。
> `Port 5173 is already in use` と表示されて起動できない場合は、すでに起動しているターミナルがないか確認し、そのアプリを止めてから起動し直してください。

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発用サーバーを起動する |
| `npm test` | 自動テストを実行する |

## 5. データの保存方式

- チケットは、ブラウザの **localStorage** に自動で保存されます（キー名：`ticket-app/v1`）。
- ゴミ箱に入れたチケットも、完全に削除するまでは保存データとバックアップに残ります（`deletedAt` に、ゴミ箱に移動した日時が入ります）。
- 登録・編集・削除・ステータス変更のたびにすぐ保存されるので、ブラウザを閉じたりページを再読み込みしたりしてもデータは消えません。
- 保存されるのは、**使っているブラウザの中だけ**です。次のような場合、データは見えなくなったり消えたりします。
  - 別のブラウザ（Chrome と Edge など）や別の PC で開いたとき
  - シークレットウィンドウ（InPrivate）で開いたとき
  - ブラウザの「閲覧履歴データの削除」で「Cookie とサイトデータ」を削除したとき
- 案件マスターも同じキーの中（`projects`）に保存し、各チケットには案件ID（`projectId`）を保存します。色は色の名前（`sky` など）で保存します。案件マスター機能を追加する前のデータ・バックアップは、すべて「案件なし」として読み込めます。
- 同じブラウザ内に、次の補助データも保存します（チケットの保存形式は変わりません）。
  - `ticket-app/v1/restore-point`：直前の復元を行う前のデータ（1回分のみ。次に復元したときに上書きされます）
  - `ticket-app/v1/last-backup-at`：最後にバックアップをダウンロードした日時
- 保存データが壊れていて読み込めない場合は、元のデータを `ticket-app/v1/corrupted-（日時）` という名前で退避したうえで、空の状態で起動します（画面上部にメッセージが出ます）。

保存方式に localStorage を選んだ理由：個人がローカルで使うことが前提なので、サーバーやデータベースの準備が要らず、導入が一番簡単なためです。
保存処理は [src/storage/ticketStorage.ts](src/storage/ticketStorage.ts) にまとめてあるので、将来サーバーやデータベースに保存する形へ変更しやすくしています。

## 6. バックアップと復元

### バックアップ（定期的に行うことをおすすめします）

1. 左のメニューから **「データ管理」** を開きます。
2. **「バックアップをダウンロード」** を押します。
3. `tickets-backup-YYYYMMDD-HHmm.json` というファイルがダウンロードされます。OneDrive などの安全な場所に保存してください。
4. 「保存状況」の「最終バックアップ」に日時が記録されます（ダウンロードを開始した日時です。ファイルが実際に保存されたかは、ダウンロードフォルダで確認してください）。

### 復元

1. 「データ管理」画面で **「バックアップファイルを選択…」** を押し、バックアップした JSON ファイルを選びます。
   - この時点ではデータは変更されません。ファイルの形式と、チケットの各項目が正しいかを確認します。
   - 正しくない場合は、原因（例：「3件目のチケットの項目「status」の値が正しくありません」）を表示し、現在のデータはそのまま残ります。
2. 「復元する内容の確認」に、ファイルの作成日時と件数（通常・ゴミ箱）が、現在のデータと並べて表示されます。
3. **「この内容で復元する…」** → 確認ダイアログの **「置き換えて復元する」** を押します。
4. 復元した件数が画面に表示されます。

> 復元すると、**今のデータはすべてバックアップの内容で置き換えられます**。
> 復元の直前に今のデータを自動で退避するので、間違えた場合は「復元前の状態に戻す」で戻せます（直前の1回分のみ）。
> 退避が保存容量の不足などで失敗した場合は、復元を中止します（今のデータは変更されません）。

別の PC やブラウザへデータを移すときも、同じ手順（移す元でバックアップ → 移す先で復元）で行えます。

## 7. フォルダ構成

```
ticket-app/
├── index.html
├── package.json
├── vite.config.ts
└── src/
    ├── main.tsx              起動処理（Router・Provider の設定）
    ├── App.tsx               画面のルーティング
    ├── styles.css            スタイル
    ├── types/ticket.ts       チケットの型定義
    ├── constants/ticket.ts   表示名・初期値などの定数
    ├── lib/                  画面に依存しない処理
    │   ├── date.ts           日付・時刻の処理
    │   ├── deadline.ts       期限の状態判定・完了の判定
    │   ├── ticketQuery.ts    検索・絞り込み・並び替え
    │   ├── stats.ts          ダッシュボードの集計
    │   ├── validation.ts     入力チェック
    │   └── ticketService.ts  登録・更新・削除（完了日時のルールを含む）
    ├── storage/ticketStorage.ts  保存・読み込み・バックアップ
    ├── state/                画面全体で共有する状態（チケット・通知）と共通操作（ステータス変更・ゴミ箱へ移動）
    ├── components/           画面の部品（ページ枠・バッジ・フォーム・テーブル・ダイアログなど）
    ├── pages/                各画面
    └── test/                 テスト用の補助（setup.ts はテスト環境の互換対応）と画面操作のテスト
```

### デザインのルール

- 色・余白・角丸・影・文字サイズ・ボタンの高さは、[src/styles.css](src/styles.css) の先頭にある CSS 変数で管理しています。変更するときは変数の値を変えてください。
- ページの見出し・説明・最大幅は共通部品 [Page](src/components/Page.tsx) でそろえています（一覧・ボード・ゴミ箱は広め、データ管理は狭め）。
- ステータス・優先度・期限の表示は [Badges.tsx](src/components/Badges.tsx) の部品を全画面で使います。
  - ステータス：点＋ラベルの淡色ピル（未着手＝グレー、進行中＝青、保留＝紫、完了＝緑）
  - 優先度：記号＋ラベル（▲高＝赤、■中＝オレンジ、▼低＝グレー）
  - 期限：日付＋状態（○日超過＝赤、本日期限＝オレンジ、あと○日＝黄色、未設定）

### 日付・時刻の扱い

- **開始予定日・期限日**：日付だけの値なので `YYYY-MM-DD`（PC のローカル日付）の文字列で保存します。タイムゾーンによって日付がずれることはありません。
- **作成・更新・完了日時**：ISO 8601 形式（UTC）で保存し、画面ではローカル時刻で表示します。
